Tilde lets your agent configure its own tools, credentials, messaging, and skills. You stay in control of approvals and external side effects.

## 1. Connect your agent

Open the setup page, choose the client where your agent runs, and connect it to the global Tilde MCP server.

<Card title="Connect your agent" icon="plug" href="/connect-your-agent" horizontal>
  Set up Codex, Claude, ChatGPT, Cursor, VS Code, or another MCP client.
</Card>

Your client connects to:

```text
https://api.trytilde.ai/mcp
```

Tilde opens a secure browser login when your client connects. Do not paste credentials into your conversation.

## 2. Tell your agent what to build

Replace the bracketed text, then send this prompt to the connected agent.

<Prompt description="Build with Tilde" icon="sparkles" actions={["copy", "cursor"]}>
Start by reading https://api.trytilde.ai/llms.txt and the hosted agent guides it links for this task. Treat them as the canonical Tilde instructions. Help me build [describe your agent] with Tilde. First inspect my Tilde identity and teams, then ask only the questions needed to understand the agent. Search Tilde's available capabilities at runtime instead of assuming which providers exist. Configure the tools, credentials, ChatKit channels, and skills the agent needs. Give me secure approval links for credentials; never ask me to paste secrets into chat. Ask before actions with external side effects. Test the setup with a read-only action, then summarize the resources you created and what I should do next. If this agent needs a cloud endpoint, prepare it for Vercel.
</Prompt>

Your agent should:

1. Reuse an existing team or help you create one.
2. Search Tilde for capabilities that match the job.
3. Show you required credentials and approvals.
4. Expose only the tools the agent needs through its MCP server.
5. Test the setup and return the resource IDs you will need later.

## 3. Start from a working example

The [code review agent](https://github.com/trytilde/examples/tree/main/code-review-bot) is a production-oriented Next.js example. It receives GitHub messages through ChatKit, runs reviews in a sandbox, and calls allowlisted GitHub tools without receiving GitHub or sandbox credentials.

Ask your connected agent to adapt it:

<Prompt description="Adapt the code review agent" icon="code-branch" actions={["copy", "cursor"]}>
Start by reading https://api.trytilde.ai/llms.txt and the hosted agent guides it links for this task. Treat them as the canonical Tilde instructions. Use https://github.com/trytilde/examples/tree/main/code-review-bot as the starting point for my agent. Read its README and tilde-state.yaml before changing code. Adapt the example to [describe the job]. Keep credentials behind Tilde, expose only required tools, and preserve webhook signature verification. Help me run it locally, complete any human approval steps, and test one safe end-to-end request. Then prepare the environment variables and production endpoint for Vercel.
</Prompt>

<Accordion title="Set up the example manually" icon="terminal">
  Clone the examples repository, then follow the project README.

  ```bash
  git clone https://github.com/trytilde/examples.git
  cd examples/code-review-bot
  pnpm install
  cp .env.example .env.local
  ```

  Import `tilde-state.yaml`, complete the pending GitHub and Modal credentials in Tilde, add the returned values to `.env.local`, then run `pnpm dev`.
</Accordion>

## Deploy to Vercel

For a cloud agent, deploy its HTTPS endpoint to Vercel. Add the server-side environment variables from the project to Vercel and keep API keys and signing keys secret.

```bash
vercel deploy --prod
```

After deployment, ask your agent to update the Tilde ChatKit agent to the production URL and run one final test.

<Note>
  The code review example allows requests that can run for up to 300 seconds. Confirm that your Vercel plan supports the required function duration.
</Note>
